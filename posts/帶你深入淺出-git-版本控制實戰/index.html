1. 版本控制是什麼？為什麼要做版本控制#

版本控制是一種管理軟體開發過程中對 code 變更的技術。它允許開發者跟蹤和管理程式碼的歷史變更，協作開發，並且可以在需要時恢復到先前的版本。

很多人作版本控制的方法是把檔案複製到另一個目錄（如果他們夠聰明的話，他們還會幫資料夾加上時間）。這種做法很常見，因為這樣做很簡單，但是卻也非常容易產生離譜的錯誤。這種做法非常容易搞混資料夾，意外寫錯檔案或複製覆蓋到不想要的檔案。

而透過「版本控制系統」可以清楚的記錄每個檔案是誰在什麼時候加進來、什麼時候被修改或刪除。Git 就是一種版本控制系統，也是目前業界最流行的版本控制系統，沒有之一。

出社會工作，有 Git 幫你保留這些歷史紀錄跟證據，萬一齣事的時候你就能知道是從什麼時候開始就有問題，以及知道該找誰負責，再也不用自己背黑鍋了！

4. 基礎概念#

Git 主要分為 4 個區塊及 4 種狀態

Git 區塊#

  • Working Directory (在此簡稱：W)：現在存在於資料夾內的、編輯器可以打開的位置。
  • Staging Area (在此簡稱：S)：暫存狀態。
  • Local Repository (在此簡稱：L)：本地（自己的電腦上的）倉庫。
  • Remote Repository (在此簡稱：R)：遠端（不在自己的電腦上的）倉庫。

Git 狀態#

  • Untracked：未被追蹤。
  • Unmodified：追蹤中，未修改。
  • Modified：追蹤中，已修改。
  • Staged：追蹤中，待提交。

    • 預設會將指定的檔案從 Staging Area 移除，但不會影響 Working Directory
    • 其他選項

遠端操作#

在講解遠端操作前，我們需要先設定好遠端倉庫的 SSH Key，這樣才能夠透過 SSH 的方式連線到遠端倉庫。

建立 SSH Key#

  • 接著輸入指令或用記事本打開公鑰。
  • 複製公鑰內容，並且將公鑰加入到遠端儲存庫的 SSH Key 設定中(以 GitHub 為例)
    • 進入 GitHub 的設定頁面
    • 選擇SSH and GPG keys
    • 按下New SSH Key
    • 在Title中輸入自己取的 SSH Key 名稱，然後在key輸入剛才的 SSH 公鑰。最後按下Add SSH Key就完成了

    • 顯示目前有哪些遠端倉庫，並且會標示預設的遠端倉庫
    • 其他選項

  • git branch：檢視目前有哪些分支

    • 會顯示目前有哪些分支，並且會標示目前所在的分支
    • 其他選項

  • git checkout <分支名稱>：切換到指定的分支

    • 其他選項

  • git push <遠端倉庫名稱> <分支名稱>：將 Local Repository 的分支推送到遠端儲存庫

    • 將 Local Repository 的分支推送到遠端儲存庫
    • 其他選項

  • git clone <遠端倉庫網址>：複製一份遠端倉庫到本地

    • 在當前目錄下建立一個資料夾，資料夾名稱就是遠端倉庫的名稱

    • 將遠端儲存庫的分支拉取到 Local Repository

5. 協作流程#

Git Flow#

  • 特點：
    • 不同分支，不同功能。
  • 優點：
    • 流程清晰可控
  • 缺點：
    • 需要同時維護 main/master 分支與 delevop 分支兩個長期分支
    • 對於中小型專案來說過於複雜且管理分支對初學者或新團隊來說會提高負擔

GitHub Flow#

  • 特點：
    • 簡化版的 Git Flow
    • Pull Request(PR)
  • 優點：
    • 只有一個長期分支 - main/master 分支
  • 缺點：
    • 正式環境更容易出問題
    • 在沒有適當測試和健全的 CI/CD、代碼審核……等過程下更容易發布問題到生產環境。

GitLab Flow#

1.持續部署 2.版本發布

特點：

  • upstream first(只有 main/master 作為主要分支)
